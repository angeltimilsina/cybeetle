# Cybeetle Chromium worker

This is Cybeetle's own browser service, with no extension or third-party browser viewer. It must run on a container host capable of launching Chromium. The ChatGPT Site remains the frontend, account service, AI service, and authenticated browser API proxy. Sites' Worker runtime does not run a Chromium executable; configuring an address is not the same as deploying this service.

## Deploy

Build this directory's Dockerfile on your container host. Expose port 8080 behind HTTPS with WebSocket upgrades enabled. Keep at least one durable instance for the MVP; sessions currently reside in process memory and require sticky routing. Scale-out session routing is not implemented.

Set `SESSION_SECRET` to a cryptographically random secret of at least 32 characters and `ALLOWED_ORIGIN` to `https://cybeetle-ai.zeal369.chatgpt.site`. Put the identical SESSION_SECRET in the Site's secret settings. Set the Site's BROWSER_BACKEND_URL to the HTTPS worker base URL and BROWSER_WS_URL to the corresponding WSS base URL. Keep OPENAI_API_KEY on the Site only. Redeploy the Site after configuration changes.

Mount persistent storage at `/data` only if persistent sessions are desired. Private contexts never write state to disk. Persistent cookies/local storage are AES-GCM encrypted with a key derived from SESSION_SECRET and saved per account only after explicit opt-in. Changing SESSION_SECRET invalidates old persistent state. Identity Vault and third-party account credential integration are not implemented.

Run Chromium with its sandbox enabled, a non-root container user, the recommended Chromium seccomp policy, and an egress policy denying private/metadata networks. The application also blocks private destinations through URL and DNS checks; infrastructure egress restrictions are necessary against DNS rebinding. Do not expose CDP ports, debug endpoints, the signing secret, or host filesystem volumes to browser pages.

## API

All HTTP calls require a short-lived HS256 capability generated by the Site. Ownership is enforced per account. The browser worker rejects streaming capabilities on HTTP routes.

- POST `/browser/session`: create isolated session (`private`, `optIn`, `width`, `height`).
- GET / DELETE `/browser/:sessionId`: inspect or close.
- POST `/browser/:sessionId/navigate`, `/click`, `/type`, `/scroll`, `/back`, `/forward`, `/refresh`, `/key`, `/mouse`, `/resize`.
- GET / POST `/browser/:sessionId/tabs`; DELETE `/browser/:sessionId/tabs/:tabId`; POST `/active`.
- GET `/browser/:sessionId/snapshot`: bounded observed DOM text and control IDs, excluding password/file controls and input values.
- POST `/browser/:sessionId/mode`, `/control`, `/permission`.
- WS `/browser/:sessionId/events`: navigation, control, session, permission and activity events.
- WS `/browser/:sessionId/view`: JPEG frame messages. Both channels are read-only and require matching account/session capabilities plus the configured Origin.

The client renews its 5-minute stream capability. Idle sessions expire after 20 minutes. Closing a private session destroys its context. Frames arrive roughly every 600 ms, not full-motion video; the interface separates the view transport so WebRTC/CDP streaming can replace it later.

## Controller and permissions

USER_CONTROLLED, AGENT_CONTROLLED and PAUSED are authoritative on the worker. Agent clicks and field entry resolve observed control IDs; no model-supplied JavaScript or selectors are executed. Ordinary non-anchor agent clicks and all field entry pause for confirmation. Consequential labels require final confirmation. Link navigation, reading, scrolling and tabs are automatically allowed. Password/file fields require manual control. Permission decisions are bound to the pending server action and are consumed once. Heuristic action classification is deliberately conservative; it is not a guarantee that every website's consequential action is identifiable. User review remains required for form interactions.

File upload controls, full-duplex realtime voice, identity vault connections, multi-worker orchestration and automatic browser-session restoration after a worker restart are not implemented. Existing manual typing and account login run only in the user-controlled viewport. Browser speech recognition and synthesis provide turn-by-turn voice commands through the same controller.

## Validation

`npm test` checks authentication scopes, URL restrictions, controller ownership, and permission classification without provider calls. `npm start` requires installed Playwright/Chromium. Run live session, frame-stream, navigation, form-confirmation and takeover tests after deployment; these cannot be validated by merely building the Site.
